# M24 bug hunt, second pass, 2026-11-20

Scope: the areas the first pass (`docs/bug-hunt/2026-11-20-m24.md`) did not test: trigger list
and editor keys, canvas text editing and pan, the multi-select Format panel, States preset
buttons, History limit note, Find & Replace status, and CLI `simulate --strict`.

Tests: `crates/ui-egui/src/bughunt_m24b_{canvas,trigger,format,misc}.rs` and new tests at the end
of `apps/coursecraft-cli/src/tests.rs` (`simulate_strict_*`). Bugs are `#[ignore = "BUG: ..."]`.
No non-test source was changed.

Run the bugs with:
`cargo test -p coursecraft-ui-egui --lib bughunt_m24b -j 4 -- --include-ignored`

## Bugs, most severe first

### 1. Cmd+B with a caret and no selection bolds the whole text box (medium, confidence high)

- **User sees:** in an on-canvas text box, put the caret somewhere (no selection) and press Cmd+B.
  The whole text becomes bold, not just the typing style for the next characters.
- **Steps:** double-click a plain text box (for example the title on `s-intro` of hello-course),
  press Right Arrow to collapse the select-all, press Cmd+B.
- **Expected:** existing text keeps its weight (the toggle applies to the typing style only).
- **Actual:** all 23 characters become bold.
- **Test:** `bughunt_m24b_canvas::cmd_b_with_caret_only_does_not_bold_the_existing_text` (ignored).
- **Likely location:** `crates/ui-egui/src/canvas.rs`, `apply_inline_edit_style_shortcut` (about
  line 4329). With no selection it passes `start: 0, end: 0`, and
  `crates/course/src/text.rs` `apply_style_to_range` treats `start == end` as the whole text.
  Fix idea: do not send a style command for a collapsed caret, or keep a typing style in the
  inline edit state and apply it to the next typed characters.

### 2. An extra click where "+ Hover" used to be adds unrelated states (low, confidence high)

- **User sees:** a fast user clicks "+ Hover" and then clicks the same spot again. The row
  reflows once "+ Hover" disappears, so the second click hits "+ Selected", and a third click hits
  "+ Visited". Three states are added with one click each.
- **Steps:** select `btn-start` on hello-course `s-intro`, Format tab, scroll until "+ Hover" shows,
  click it, then click the same spot twice more.
- **Expected:** extra clicks add nothing else.
- **Actual:** states `hover`, `selected`, `visited` exist; undo history shows three "New State" steps.
- **Test:** `bughunt_m24b_misc::plus_hover_clicked_twice_adds_one_state_and_one_undo_step` (ignored).
- **Likely location:** `crates/ui-egui/src/states.rs`, the shortcut row (about line 189–200):
  buttons hide and the row reflows. Fix idea: keep the row's buttons in place (disable instead of
  hide), or require a pause before the next click registers.

### 3. Middle-button drag does not pan the canvas in the harness (unconfirmed, low confidence)

- **Test:** `bughunt_m24b_canvas::middle_mouse_drag_pans_without_moving_the_object` (ignored).
- **Observed:** a middle-button press, move and release over the slide left the slide rect
  unchanged. Space-drag pans in the same harness, so the cause may be in how the harness sends the
  middle button, or in `canvas.rs` `pan_active` (about line 5440, `middle_down`). Not yet ruled out as a
  harness artefact. Check in the running app before filing.

## Not a bug (checked)

- The first full run of the middle-pan test moved nothing with the pointer over a button and nothing
  over empty canvas. The test is kept as ignored, not counted above as confirmed.
- The Find & Replace "Replaced N." status stays after Undo only while the Find window is closed; it
  clears when the window is next drawn (`find.rs` line 272). Not user-visible.
- The History limit note stays after undoing back below 200 steps. Correct: the dropped steps are gone.

## What I tested that worked

- Trigger list: a filter with no matches shows the message; regex-like needles (`.*`, `[(`, `\`, `(?i)`)
  match nothing literally and do not panic; mixed-case filter text matches; "Group by object" shows a
  `Slide` header for slide-level triggers; a narrow 1100x700 window with a filter has no layout
  findings; Cmd+Enter on a new (default) trigger does not add validation problems; two Cmd+Enter in a row
  save exactly one trigger; Move up on the first row and Move down on the last row change nothing and add
  no undo step; reorder then undo then redo restores each order; a new trigger on a selected layer
  object (`s-intro` layer "about") defaults to that object.
- Canvas text: Space while editing types a space and does not pan; Space-drag while editing does not
  move the object or pan; Cmd+B with a partial selection (5 characters) bolds only those 5; Cmd+B then
  Undo restores the course JSON exactly, in one undo step; Cmd+B / I / U on a button not being edited do
  nothing and add no undo step.
- Format panel: a mixed selection (text, button, shape, image) gets one opacity change as one undo step;
  Undo restores every object's JSON exactly.
- States: + Hover adds `hover`; Undo removes it (in the single-click case).
- History: after 205 undoable steps the History window shows the "Older steps were removed (CourseCraft
  keeps the last 200)." note and it stays after 10 undos.
- CLI: `simulate --strict` exits 0 on hello-course `pass.inputs.json`, and exits non-zero when a click
  targets an object that is on a hidden layer (`about-panel`). The existing `test_cli_simulate_strict_fails_on_warning`
  also passes.

- CLI `simulate --strict` message: the strict failure prints the warning as a JSON line on stdout and

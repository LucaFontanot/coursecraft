## Findings

### 1. Find & Replace (and XLIFF placeholder check) corrupts built-in variables containing dots

- **Severity:** High (regression in 0.2.5)
- **Status:** Confirmed
- **Where:** `crates/course/src/strings.rs:783-815` (`variable_reference_spans`), calling `crates/course/src/validate.rs:52-57` (`valid_name`).
- **Trigger:**
  1. Have a Results or Certificate slide with text such as `"You scored %Results.ScorePercent%! Awarded to %Course.LearnerName%."`.
  2. Open Find & Replace (`Ctrl+H`) and replace `"Score"` with `"Grade"` (or `"Course"` with `"Module"`).
- **Effect:** `variable_reference_spans` was tightened in 0.2.5 to accept a `%...%` span only when `crate::validate::valid_name(name)` is true. `valid_name` only allows `[A-Za-z0-9_-]` and rejects `.`, which every CourseCraft built-in variable contains (`Results.ScorePercent`, `Course.LearnerName`, `Project.SlideNumber`, etc.). As a result, `variable_reference_spans` returns `[]` for built-in variables, Find & Replace silently mutates `%Results.ScorePercent%` into `%Results.GradePercent%` (breaking the placeholder at runtime), and XLIFF placeholder validation (`crates/format/src/xliff.rs`) stops recognizing built-in variables.
- **Suggested fix:** Accept `crate::validate::valid_name(name) || crate::builtin_variable_kind(name).is_some()` (or allow `.` in variable-reference names) in `variable_reference_spans`.
- **Test name:** `crates/course/src/bughunt_m25_strings.rs::builtin_variable_reference_is_protected_in_find_and_replace`

### 2. Version History snapshots of plain `course.json` projects are saved as `.ccraft` and cannot be listed or opened

- **Severity:** High (regression in 0.2.5)
- **Status:** Confirmed
- **Where:** `apps/coursecraft/src/main.rs:639-650` (`save_project_file`, `SaveKind::Json` calls `self.keep_version(&path)`), `apps/coursecraft/src/versions.rs:168-170` (`version_file`) and `:193-196` (`describe`), `apps/coursecraft/src/main.rs:714-735` (`open_version_copy`), `apps/coursecraft/src/files.rs:465-485` (`open_from`).
- **Trigger:**
  1. Open a plain `course.json` file (e.g., `examples/hello-course/course.json`) in the desktop editor.
  2. Edit and press Ctrl+S (`SaveKind::Json` now writes JSON instead of a zip).
  3. Open **File → Version History** and click **Open Copy** on the saved version.
- **Effect:** `snapshot_before_save` copies the plain JSON file into `<config_dir>/versions/<hash>/<timestamp>.ccraft`. Because the snapshot file has a `.ccraft` extension but contains plain JSON:
  - `versions::describe` calls `coursecraft_format::read_course` (ZIP reader), which fails, leaving `slides: None` and causing `latest_readable` to skip it.
  - `open_version_copy` calls `files::open_from`, which only parses plain JSON when the extension is `.json`; on `<timestamp>.ccraft` it tries to open a ZIP and fails with `"This file can't be opened. It may be damaged or not a CourseCraft project."`.
- **Suggested fix:** Either skip version snapshots for bare `.json` files (like folder projects), or preserve the `.json` extension (and teach `versions::ids`, `versions::describe`, and `versions::version_path` to handle `.json` snapshots as well as `.ccraft`).
- **Test name:** `apps/coursecraft/src/bughunt_m25_versions.rs::json_project_version_snapshot_is_readable_and_openable`

### 3. Inserting a shared library template (or cross-course `slide.paste`) fails when the slide has a `Link::Slide` or `next_requires` variable not in the target course

- **Severity:** High (new feature in 0.2.5)
- **Status:** Confirmed
- **Where:** `crates/engine/src/commands.rs:4199-4329` (`copy_slide`) and `:2507-2519` (`slide_paste`); `crates/ui-egui/src/lib.rs:1777-1821` (`Editor::insert_library_template`).
- **Trigger:**
  1. In Course A, create a slide containing either a text run with a slide link (`Link::Slide { slide: "s-other" }`) or a slide player override `next_requires: Variable { name: "course_a_flag" }`.
  2. Save the slide as a template, save it to **My library**, open Course B (which does not contain `"s-other"` or `"course_a_flag"`), and insert the template from **My library** (or copy/paste the slide into Course B).
- **Effect:** `copy_slide` strips triggers referencing missing slides/variables, and `insert_library_template` clears a missing `slide.master`, but neither strips missing `Link::Slide` links from text/shape runs nor clears a missing `slide.player.next_requires` variable. `slide.paste` then fails `keep_valid` with `Err(Invalid("link target slide ... does not exist"))` or `Err(Invalid("variable ... does not exist"))`, completely refusing to insert the template. In addition, `insert_library_template` appends the template's media to `self.media` *before* calling `self.run("slide.paste", params)`, leaving orphan media in memory when `slide.paste` fails.
- **Suggested fix:** In `copy_slide` (when `allow_missing_jump` is `false`), strip `Link::Slide` targets that do not exist in `course` (remapping `self_slide` to `new_slide_id`) and clear `slide.player.next_requires` if it references a variable not in `course`. In `insert_library_template`, only commit added media after `slide.paste` succeeds (or roll it back on failure).
- **Test names:**
  - `crates/engine/src/bughunt_m25_engine.rs::slide_paste_from_other_course_drops_missing_slide_link`
  - `crates/engine/src/bughunt_m25_engine.rs::slide_paste_from_other_course_clears_missing_next_requires_variable`

### 4. Inserting a shared library template with a case-only media name collision breaks saving as a project folder

- **Severity:** High (new feature in 0.2.5)
- **Status:** Confirmed
- **Where:** `crates/ui-egui/src/lib.rs:1791-1806` (`Editor::insert_library_template`) and `crates/format/src/folder.rs:419-421` (`save_project_folder_with`).
- **Trigger:**
  1. Open a course (saved as a project folder) that uses `Logo.png`.
  2. Insert a template from **My library** that uses `logo.png` (different bytes, differing only in case).
  3. Save the project folder.
- **Effect:** `insert_library_template` checks for collisions using case-sensitive `name == &src`. It fails to see that `logo.png` collides with `Logo.png`, so both remain in `self.media` and `used_media()`. When saving as a project folder, `save_project_folder_with` checks `wanted.insert(format!("media/{path}").to_ascii_lowercase())` and rejects the save with `FormatError::DuplicateEntry("logo.png")`. (Note: `sanitize_font_src` at `crates/ui-egui/src/lib.rs:4370` has the same case-sensitive `src == &name` check.)
- **Suggested fix:** Compare media names with `eq_ignore_ascii_case` in `insert_library_template` (and `sanitize_font_src`), and rename via `sanitize_media_src` whenever a case-insensitive collision with different bytes (or different casing) occurs.
- **Test name:** `crates/ui-egui/src/bughunt_m25_templates.rs::insert_library_template_avoids_case_only_media_collision_for_folder_save`

### 5. Headless MCP `file.save` to a project folder drops all media

- **Severity:** Medium (incomplete fix in 0.2.5)
- **Status:** Confirmed
- **Where:** `crates/control/src/host.rs:389-463` (`HeadlessHost::save`) and `:465-501` (`HeadlessHost::open`).
- **Trigger:**
  1. Open a `.ccraft` project containing media (e.g., `hero.png`) via `coursecraft-mcp` (`HeadlessHost::open`).
  2. Call `file.save` with a folder path (e.g., `out.ccraft-folder`).
- **Effect:** 0.2.5 fixed `HeadlessHost::save` for `.ccraft` archives and fixed the desktop control host for project folders, but `HeadlessHost::save` still takes the `else` branch for directories and writes only `course.json`, dropping every media file. Similarly, `HeadlessHost::open` on a folder clears `in_memory` media and only reads `course.json`, so opening a folder project and saving it as `.ccraft` via MCP also drops all media.
- **Suggested fix:** Use `coursecraft_format::save_project_folder` (with `self.media_source.snapshot_in_memory()`) when `HeadlessHost::save` targets a folder, and `coursecraft_format::open_project_folder` when `HeadlessHost::open` opens a directory.
- **Test name:** `crates/control/src/bughunt_m25_host.rs::headless_host_save_to_folder_preserves_media`

### 6. Clicking "Start over" in Publish to Web resets player speed to 1x but leaves HTML5 media playback rate unchanged

- **Severity:** Medium (new feature in 0.2.5)
- **Status:** Traced
- **Where:** `apps/coursecraft-player/src/app.rs:359-379` (`Playing::restart`).
- **Trigger:**
  1. Open a Publish to Web course with narration or video.
  2. Change playback speed to `2x`.
  3. Click **Start over** (`Playing::restart`).
- **Effect:** `Playing::restart` replaces `self.player` with a fresh `1.0x` `Player` and calls `self.frame.restart()`, so the speed button shows `1x` and the slide timeline/captions advance at `1x`. Unlike desktop preview (`crates/ui-egui/src/preview.rs:628`), `Playing::restart` does not call `self.media.set_rate(1.0)`. `WebMediaBackend::rate` remains `2.0`, so newly started audio/video elements continue playing at `2x` out of sync with the timeline and captions.
- **Suggested fix:** Add `self.media.set_rate(1.0);` in `Playing::restart` before `self.handle_input(&Input::Start, ctx)`.

### 7. Web editor Save / Save As bundles deleted/unused media into the downloaded `.ccraft`

- **Severity:** Low (new feature in 0.2.5)
- **Status:** Traced
- **Where:** `apps/coursecraft/src/main.rs:3181-3185`.
- **Trigger:**
  1. In the web editor, import a large image or video, then delete the object from the slide.
  2. Click **File → Save** or **Save As**.
- **Effect:** Desktop save calls `self.editor.used_media()` (`apps/coursecraft/src/main.rs:619`), whereas the wasm `EditorRequest::Save | EditorRequest::SaveAs` handler passes `&self.editor.media` directly to `coursecraft_format::save_project`, bundling deleted/unused media into the downloaded `.ccraft` archive.
- **Suggested fix:** Pass `&self.editor.used_media()` to `save_project` in the wasm Save / SaveAs handler.

## Checked, no issues found

- **Runtime caches and fixes (`crates/logic`):** `SlideCache` (`has_intersection_trigger`, `pointer_trigger_objects`) is refreshed on `new`, `resume`, `enter_slide`, `enter_lightbox_slide`, and `close_lightbox`. `Player::resume` / `resume_trusted` sets `entered = state.started` correctly. `retry_quiz`, `review_quiz`, and `exit_review` close an open lightbox first, and `retry_quiz` runs leave steps before replacing `self.slides` when banks are present.
- **Engine validation cache and command fixes (`crates/engine`):** `valid_at_revision` is invalidated on batch mutations, `undo`, and `redo`. `edit.undo` / `edit.redo` are rejected inside batches. `remove_dangling_triggers` removes in descending index order across scenes and banks. `object.remove_motion_path` removes referring triggers and calls `keep_valid`. `slide_size.rs` scales guides, paragraph spacing, and text styles.
- **Folder project case-only media delete protection (`crates/format/src/folder.rs`):** `put_all` / `take` and `delete_unused` handle case-only renames safely (`eq_ignore_ascii_case`, lowercased `wanted` set).
- **Shortcut handling while typing (`crates/ui-egui/src/lib.rs`):** `text_focus` gates the registry shortcut loop, `Ctrl+Shift+Z`, `F7`, and format painter shortcuts cleanly.
- **Canvas drag over HUD/rulers/guides (`crates/ui-egui/src/canvas.rs`):** `pointer_in_hud` only gates starting a new gesture (`!pointer_in_hud || gesture_active`), so active drags continue smoothly over HUD and guides.
- **Desktop playback speed (`crates/playback/src/lib.rs`, `crates/ui-egui/src/preview.rs`):** `set_rate` applies to active and newly created rodio sinks and video workers, and `Preview::restart` resets `self.media.set_rate(1.0)`.
- **PPTX/DOCX entity decoding (`crates/pptx/src/lib.rs`):** `parse_xml_tree` handles `Event::GeneralRef` (char refs + standard XML entities) and `Event::CData`, and hidden-slide links are dropped.
- **LMS & LTI (`crates/lms/src/bridge.rs`, `apps/coursecraft-lti/src/server.rs`):** SCORM/LTI pass protection prevents overwriting a pass with a fail or lower score; LTI `ETag`, `If-None-Match`, and `Range` byte-range parsing handle empty files, suffix ranges, and out-of-bounds ranges cleanly.
- **CLI smoke tests (`coursecraft-cli`):** `validate` passed with 0 errors/warnings on `examples/hello-course`, `examples/healthy-habits`, and `examples/showcase`; `simulate --strict` and `publish --standard web` succeeded on `examples/hello-course`.

# M24 bug hunt, 2026-11-20

Scope: the M24 changes (inline rename, timeline seconds, publish memory, deferred audit,
trigger and canvas speed work, daily fixes, preview server, CLI checks). Tests live in
`crates/ui-egui/src/bughunt_m24_{rename,canvas,stress}.rs` and
`apps/coursecraft/src/bughunt_m24_preview.rs`. Bugs are marked `#[ignore = "BUG: ..."]`, so
the normal suite stays green. No non-test source was changed.

Run the bugs with `--include-ignored`:
`cargo test -p coursecraft-ui-egui --lib bughunt_m24 -j 4 -- --include-ignored`
and `cargo test -p coursecraft --bin coursecraft preview -j 4 -- --include-ignored`.

## Bugs, most severe first

### 1. Publish adds an undo step (medium, confidence high)

- **User sees:** after a successful Publish with a different standard, the first Cmd+Z
  does not undo the last visible edit. It quietly reverts the remembered publish standard,
  which the author does not see. The Undo menu also gets a "view.set" entry.
- **Steps:** open File > Publish (or the Publish dialog), choose "Web (any website, no LMS)",
  press Publish. Check the undo count (or press Cmd+Z).
- **Expected:** remembering the standard is not an edit; undo count unchanged.
- **Actual:** undo count goes from 0 to 1.
- **Test:** `bughunt_m24_rename::publish_remembered_standard_is_not_an_undo_step` (ignored).
- **Likely location:** `crates/ui-egui/src/publish.rs` around line 340, where the Publish
  button runs `view.set` with `last_publish`. `view.set` (`crates/engine/src/commands.rs`,
  about line 5425) only skips the undo entry when nothing changed. Fix idea: store the
  standard without an undo entry (for example a non-undoable settings write), or skip undo
  for this key.

### 2. Publish without --player reports the wrong problem when a half-built player folder exists (medium, confidence high)

- **User sees:** `coursecraft-cli publish ... --standard web` prints
  `publish error: player files must contain index.html` and never says to run
  `cargo xtask build-player`.
- **Steps:** have a `target/player-dist` folder that exists but has no `index.html` (for
  example `course.json` and `.trunk-lock` left by an interrupted trunk build). Run publish
  without `--player` from a folder that can find it. Reproduced in this worktree at
  `target/player-dist`, which holds only `course.json` and `.trunk-lock`.
- **Expected:** the discovery step skips folders without `index.html`, so the error says
  how to build the player (the M24 step 10c requirement).
- **Actual:** `resolve_player_dir` accepts any existing directory, so the publish stage
  fails later with the generic message.
- **Likely location:** `apps/coursecraft-cli/src/lib.rs`, `resolve_player_dir` (about line
  1138). Fix idea: require `index.html` inside each candidate.

### 3. A slide deleted mid-rename leaves the rename open (low, confidence medium)

- **User sees:** nothing visible. The inline rename field stays in editor state for a slide
  that no longer exists, and a later Enter does not close it until the next click.
- **Steps:** double-click a slide title to start rename, type, then delete that slide
  (for example through the command path) before pressing Enter.
- **Expected:** rename closes when its slide is gone.
- **Actual:** `ui.slide_rename` is still `Some` after the next frame.
- **Test:** `bughunt_m24_rename::rename_then_delete_the_slide_leaves_no_rename_open` (ignored).
- **Likely location:** `crates/ui-egui/src/slides.rs`, `show_slide_rename_editor` (about line
  534). Fix idea: clear `slide_rename` when `course.slide(rename.scene)` is `None`.

### 4. One stalled connection blocks the preview server for 5 s (low, confidence high)

- **User sees:** after "Open in browser", a page that opens a connection and sends nothing
  (or a slow request) makes the next page load wait about 5 s.
- **Steps:** connect to the preview port and send nothing, then request `/`.
- **Expected:** the valid request is served at once.
- **Actual:** the accept loop handles connections one at a time, so the request waits for the
  5 s read timeout of the stalled one.
- **Test:** `bughunt_m24_preview::stalled_client_does_not_block_other_requests` (ignored).
- **Likely location:** `apps/coursecraft/src/preview_server.rs`, the accept loop in
  `start_from_zip_bytes` and `handle_connection`. Fix idea: handle each connection on its own
  short thread, or shorten the read timeout.

### 5. A zip entry named `./index.html` is not served at the root (low, confidence medium)

- **User sees:** a blank 404 page if a zip contains `./index.html`. Publish writes plain names,
  so this does not happen in practice today.
- **Test:** `bughunt_m24_preview::zip_with_dot_slash_entry_is_not_served_at_root` (ignored).
- **Likely location:** `apps/coursecraft/src/preview_server.rs`, `read_zip_entries`
  (strip a leading `./` as well as `/`).

## Not reproduced (checked and ruled out)

- A plain drag and an Alt-drag of a locked object do not move or copy it. An early failure
  came from the test using `object.update` with a `locked` patch, which does nothing. The
  real command is `object.lock`. Confidence high.
- Two inline slide renames in a row: an early failure came from the harness. Two double-clicks
  in the same egui instant merge, so the test now advances egui time between them.
- Timeline seconds with `NaN`, `inf`, `0`, `-5`, `1e9`, `abc`, `2.5s`, `2,5`, `0.04`: every
  value stays in 100..=86 400 000 ms. Undo restores the previous value.

## What I tested that worked

- Rename: long emoji name with padding (trimmed, undone); same title adds no undo step;
  two renames undo one at a time and redo; rename while another slide is selected renames the
  double-clicked slide; click another slide mid-rename commits to the renamed slide; Esc
  cancels with no undo step.
- Timeline duration: hostile inputs above; undo restores 5000 ms after typing 0.5.
- Audit debounce: the panel opened mid-quiet-time matches a direct `course.audit` run.
- Canvas: Alt-drag of a two-object selection adds two copies and one undo removes both; Alt-drag,
  undo, redo restores the copy; Alt-drag of a locked object does nothing; a bare Space press
  leaves the course unchanged.
- Variables: duplicate name refused by the engine; names outside `[A-Za-z0-9_-]` (including
  spaces and emoji) are refused with "must be 1-128 chars of [A-Za-z0-9_-]".
- Random walk (`bughunt_m24_stress`, 2000 steps, seed 0x0B164D241120, healthy-habits, keys F2,
  Space, Escape, Enter, Delete, arrows, Cmd+B/I/U/Z, Shift+Cmd+Z, Alt/Shift/plain drags,
  right-clicks, double-clicks): no panic, no new validation errors, undo-all returns the
  original course. Runs in about 54 s, so it is `#[ignore]`d. 78 undos applied.
- CLI: `validate` on hello, healthy-habits and showcase reports 0 errors and 0 warnings;
  a build script, a CSV, an inputs file, malformed JSON and an empty file each get a plain
  message and exit 2; `simulate` on every example inputs file runs.
- Preview server: `%2e%2e`, `%2E%2E%2F`, `..%2f`, `%5c` and NUL are refused; backslash is
  refused; query strings cannot smuggle traversal; truncated and invalid percent escapes are
  kept literally; a very long path (60 000 characters) does not panic; an empty connection and
  a request without a newline both finish within the timeout; HEAD gets 405; a bare `GET` gets 400;
  a zip with a leading-slash entry is served at the root.

  tests written, for time.
- Canvas text editing: Space-drag while a text box is being edited, Cmd+B/I/U with and without
  a selection, and their undo. These need an inline text edit set up in the harness.
- Format panel multi-select: opacity, outline, font and animation applied to a mixed selection
  (text, shape, button, image) and one Undo. Not written.
- Publish round trip: the standard after save and reopen was covered by existing
  `publish_tests.rs`. Not extended.
- States preset buttons, Enter in the variable field through the UI, double-click media insert

- CLI `simulate --strict` non-zero exit: no example run produced a runtime warning, so the
  exit path was not exercised.

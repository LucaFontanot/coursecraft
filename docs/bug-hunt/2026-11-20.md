# Bug hunt, 2026-11-20

Headless QA of the egui editor (`coursecraft-ui-egui`) and the engine
(`coursecraft-engine`), plus CLI checks on the examples. Nothing in non-test
source was changed. Each bug has an ignored test that asserts the correct
behaviour; run them with:

```sh
cargo test -p coursecraft-ui-egui --lib bughunt -j 4 -- --include-ignored
```

Summary: 4 bugs with ignored tests: 1 crash and 2 high in the editor, and 1
medium in the engine (item 4). Four low findings or design notes (items 5 to 8)
cover the undo cap, the CLI and the docs.

---

## 1. Crash: Freeform question condition editor panics (High, crash)

**What a user sees.** Open a Freeform question that has a "Correct when"
condition (the healthy-habits sample has one on slide `q9`), with the Question
tab showing. The editor panics and the app closes.

**Steps.** Open `examples/healthy-habits/course.json`. Select slide `q9`
(freeform question). Set the bottom panel to the Question tab. Render a frame.

**Expected.** The condition editor draws; no panic.

**Actual.** `panicked at egui-0.37.0/src/ui.rs:2372: You can only indent
vertical layouts, found Layout { main_dir: LeftToRight, ... }`.

**Test.** `bughunt_insert::freeform_question_condition_editor_renders_without_panicking`
(ignored). The random-walk stress test also stops on this panic at step 497.

**Likely location.** `crates/ui-egui/src/triggers.rs`, `render_condition_group`:
`ui.indent(...)` is called inside `ui.horizontal(...)` (around line 2904-2916).
It is reached from `question.rs::show_freeform` (around line 601). egui uses
`assert!` for this check, so release builds panic too.

**Confidence: high.** Reproduced deterministically with no random input.

## 2. Click-through: a press that closes a menu over the slide list also switches the slide (High)

**What a user sees.** A Fill type menu is open in the Format panel. The user
clicks away on the slide list to close it. The menu closes, but the slide
under the pointer also opens, the object selection drops, and the inspector
jumps to Slide. This is the same bug already fixed for Slide Layers, in the
slide navigator.

**Steps.** Open `examples/healthy-habits/course.json` at 1100x700. Select
`w_start` on slide `welcome` and open the Format tab. Click the Fill type
combo ("Solid"). Click the centre of the slide list.

**Expected.** Menu closes. Slide stays `welcome`, `w_start` stays selected,
inspector stays on Format, and the course is unchanged.

**Actual.** Menu closes, slide becomes `name`, object selection becomes `None`,
inspector tab becomes Slide. (Control: the same click with no menu open also
selects `name`, so the press reached the navigator.)

**Test.** `bughunt_menus::clicking_away_from_fill_menu_over_the_slide_list_changes_nothing`
(ignored). The canvas and timeline versions pass
(`clicking_away_from_fill_menu_over_each_panel_changes_nothing`).

**Likely location.** `crates/ui-egui/src/slides.rs`, `show_slides_panel`. The
slide navigator does not call `widgets::pointer_reaches`, which the canvas,
rulers, timeline and Slide Layers use to ignore presses that began over a
popup (see the doc comment at `widgets.rs` around line 25).

**Confidence: high** for the behaviour. Medium for the exact fix point.

## 3. Cmd+Shift+Z undoes instead of redoing (High on a Mac)

**What a user sees.** A Mac user presses Cmd+Shift+Z (the standard redo key).
The last change is undone, not redone. Redo only works with Cmd+Y (Ctrl+Y in
the registry). The Edit menu shows only "Ctrl+Y" for Redo.

**Steps.** Open healthy-habits. Nudge `w_title` with the right arrow (or
delete `w_chip`). Press Cmd+Z, then Cmd+Shift+Z.

**Expected.** The nudge (or delete) comes back.

**Actual.** The course goes back to the original again. Cmd+Y does redo.

**Test.** `bughunt_undo::cmd_shift_z_redoes_after_common_actions` (ignored).
Passing: `undo_redo_after_common_object_actions` and
`undo_redo_after_common_structure_actions`, which redo with Ctrl+Y.

**Likely location.** `crates/engine/src/commands.rs`, `edit.redo` (around line
256) has `shortcut: Some("Ctrl+Y")` only. Shift+Z matches the Ctrl+Z binding
(`edit.undo`, around line 247) in egui's shortcut matching, so the press runs
undo.

**Confidence: high** that Shift+Z does not redo, which is what the test
checks. Medium on the mechanism: the test shows it runs undo, not why.

## 4. Insert Question > Freeform is refused when the first variable is not a number (Medium)

**What a user sees.** Insert Question > Freeform on a course whose first
variable is a Boolean (healthy-habits: `flip_card1`) does nothing. The Question
panel does not change. The only hint is a status message: `"flip_card1" is
Bool, compared with Number (/scenes/0/slides/0/question/correct_when)`.

**Steps.** Open healthy-habits. Select slide `welcome`. Insert > Question >
Freeform.

**Expected.** A freeform question with a sensible default condition is added.

**Actual.** Refused by validation.

**Test.** `bughunt_insert::freeform_question_insert_works_when_the_first_variable_is_a_boolean`
(ignored).

**Likely location.** `crates/engine/src/commands.rs`,
`freeform_default_condition` (around line 10403). It uses
`course.variables.first()` without checking its type. It always builds
`Compare { op: Ge, value: Number(0.0) }`.

**Confidence: high.**

## 5. Stress walk cannot finish: undo history is capped at 200 steps and drops the oldest silently (Low, design)

Not a bug on its own, but it limits what undo-all can prove. `MAX_HISTORY` is 200
(`crates/engine/src/lib.rs` line 29). Once it is full, the oldest step is
dropped with no message, so Cmd+Z cannot reach the original course after
more than 200 edits. The stress test checks that the cap is not reached
before its undo-all check.

**Confidence: high** for the cap. Whether users need a warning is a product call.

## 6. CLI: documented `publish` command fails (Low, docs)

`docs/cli.md` line 111 documents `publish <course> -o <zip> [--standard <std>]`.
The CLI rejects that form: `error: the following required arguments were not
provided: --player <PLAYER>`. The help text does not say the player is needed.
Line 68 of the same doc says it comes from `cargo xtask build-player`, which
needs `trunk`. A user following line 111 is stopped at the first step.

Packaging works once a player folder is supplied. With a stub `index.html`
folder, all five standards (`scorm12`, `scorm2004`, `cmi5`, `xapi`, `lti`) built
without errors. The real player was not built here (see "not tested").

**Confidence: high.**

## 7. CLI: `simulate` exits 0 when the inputs do not match the course (Low)

`simulate examples/hello-course/course.json examples/healthy-habits/pass.inputs.json`
prints many `{"effect":"warning","message":"object \"n_entry\" is not on this slide"}`
lines and exits 0. A CI step that runs `simulate` would pass.

**Confidence: high** (observed exit 0).

## 8. CLI: wrong file type gives a confusing error (Low)

- `validate examples/batch/rebrand.json` (a script, not a course) prints
  `invalid type: map, expected u32 at line 2 column 2`.
- `validate examples/questions.csv` prints `expected ident at line 1 column 2`.

Neither says "this looks like a script/CSV, not a course". Missing files are
reported clearly (`No such file or directory`).

**Confidence: high.**

## Harness notes (not bugs)

- Cmd+C and Cmd+V are platform `Event::Copy` and `Event::Paste(text)` in this
  app (`lib.rs` around line 3138), so the tests send those events. Sending only
  Key events does nothing in the harness, as a real platform would also send
  the events.
- The publish checks used a stub player folder (`target/bughunt/stub-player`),
  not a real build.

## What was tested and worked

**Insert (all three window sizes, 1100x700, 1280x800, 1280x900).** Text box,
rectangle, rounded rectangle, ellipse, button, table, text entry, slider, dial,
checkbox, radio group, marker, timer, progress meter, scroll panel, and seven
question kinds (multiple choice, multiple response, true/false, fill-in,
sequence, matching, Likert). Each new object's Format panel gave no clipped,
overlap or off-window findings, and one Cmd+Z restored the course exactly.

**Fill type dropdown.** Solid, Linear gradient and Radial gradient each keep
the selection and the Format tab, add exactly one undo step, and undo restores
the course.

**Menus over other panels.** Clicking away from the open Fill type menu over
the canvas and the timeline changes nothing. Picking a menu item does not
switch the slide.

**Undo and redo (Ctrl+Z, Ctrl+Y).** Nudge, delete, duplicate, copy and paste,
group, add slide, add scene, add layer, and insert text box each add one undo
step. Undo restores exactly and redo reapplies. Undo with empty history does
nothing. A new action after undo clears redo.

**Layout.** No clipped, overlap or off-window findings in any Format panel
checked.

**Engine.** A failed command adds no undo step and changes nothing. Undo with
empty history is an error. Add, undo and redo are exact. Huge and negative frame
numbers (`1e38`, `-1e38`, negative size) do not panic, and the course still
serialises and validates.

**Stress walk.** Seeded (`0x5EED_2026_1120`), 2000 random clicks, right clicks,
drags, arrow and Delete keys, Cmd+D, Cmd+C/V, Cmd+G, Cmd+A, undo, redo and slide
selects. It stops at step 497 on the bug in item 1.

**CLI.** `validate` passed for hello-course, healthy-habits and showcase. `a11y-check` passed with no errors:
hello-course and showcase had no findings; healthy-habits had 29 notes (contrast
over images, which need a person), no errors. `simulate` passed with the
`pass.inputs.json` files for hello-course, healthy-habits and showcase, and
showcase `fail.inputs.json` ends with `"status":"failed"` as expected. `publish`
packaged hello-course for all five standards, and healthy-habits and showcase
for scorm12, into `target/bughunt/`.

## What could not be tested

- Animate and Slide tab dropdowns. Only the Fill type combo was covered; there
  is no generic combo finder in the harness.
- Trigger, variable and rename undo, and adding a variable (dialog-driven).
- Escape, Delete and Cmd+Z while a text field has focus. Focusing a field
  headlessly was not reliable enough to test.
- Mouse drag-move and resize of objects. Only arrow-key nudge was tested.
- Image, video, audio, Lottie and web inserts (they need files or network).
- Window sizes other than the three listed, and the light theme.
- The full stress walk. It cannot run past the item-1 panic. Its runtime is
  about 16 s to that point (the whole ui-egui bughunt suite with ignored tests
  runs in about 18 s). Once item 1 is fixed the walk may take longer.
- A real `publish` with a built player. It needs `cargo xtask build-player`
  (trunk is installed, but the player was not built).
- Keyboard shortcuts for every menu item.
